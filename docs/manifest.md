# Справочник манифеста

Манифест — файл `office.yaml` в корне проекта. Офис читает его при старте, проверяет и отказывается стартовать,
пока есть ошибки (все ошибки печатаются сразу, см. [errors.md](errors.md)). Поменял манифест — перезапусти офис.

Форма манифеста задана JSON-схемой `manifest.schema.json` из пакета (`…/@tihonove/agent-office/dist/manifest.schema.json`).
Первая строка `office.yaml` подключает её к редактору (подсказки ключей, описания, подчёркивание ошибок):

```
# yaml-language-server: $schema=./node_modules/@tihonove/agent-office/dist/manifest.schema.json
```

Путь относительно `office.yaml`; при глобальной установке — абсолютный путь из `npm root -g`.
Лишних ключей схема не пропускает: опечатка в имени ключа — ошибка старта, а не молча проигнорированная строка.

## Минимальный манифест

Одна роль, одна заявка: роль берёт новую заявку и закрывает её.

```yaml
inbox: { kind: заявка, state: новая }

kinds:
  заявка:
    states: [новая, в работе, готово]
    closed: [готово]

executors:
  claude: { type: claude, model: sonnet, args: [--permission-mode, acceptEdits] }

roles:
  исполнитель:
    executor: claude
    prompt: office/roles/исполнитель.md
    when: { kind: заявка, state: новая }
    needs: [описание]
    arrows:
      start: в работе
      outcomes: { готово: готово }
```

Полные рабочие манифесты — в [recipes.md](recipes.md).

## Разделы

| Ключ | Обязателен | Что это |
|---|---|---|
| `inbox` | да | род и состояние, в которых рождается заявка человека |
| `kinds` | да | роды узлов и их состояния |
| `executors` | да | исполнители ролей: `claude` или `fake` |
| `roles` | да | роли: кто, когда и с каким входом нужен узлу |
| `transitions` | нет | переходы по условию: ответ человека, дети, артефакт |
| `spawns` | нет | какой артефакт создаёт дочерние узлы |
| `requests` | нет | когда офис сам спрашивает человека и что будет при молчании |
| `resources` | нет | ёмкости, которые агенты делят между собой: сколько кого может работать одновременно |
| `areas` | нет | карта областей проекта для ролей |
| `askDeadline` | нет | дедлайн вопросов агентов по умолчанию; без него — `24h` |

Длительности везде — число и единица `s|m|h|d`: `30m`, `24h`, `3d`. Без пробела внутри, без дробей.

### `inbox`

```yaml
inbox: { kind: заявка, state: новая }
```

Заявка из дашборды рождается здесь. Состояние должно быть у этого рода. Чтобы заявку кто-то подхватил,
нужна роль с `when` на это состояние. Если человек в дашборде выберет другой род, узел родится в первом состоянии
из `states` того рода.

### `kinds`

```yaml
kinds:
  заявка:
    states: [новая, анализ, к реализации, реализация, приёмка, готово, отклонена, отложена]
    closed: [готово, отклонена, отложена]
```

- `states` — все состояния рода. Любое состояние, упомянутое где-либо в манифесте, должно быть здесь.
- `closed` — конечные состояния. Влияют только на потолок `maxOpen` у порождений: закрытый ребёнок не занимает место.
  Агентов офис поднимает по предикатам ролей, а не по `closed` — закрытость для него не особое состояние.

Типичный набор: состояние-очередь перед ролью (`к реализации`) и состояние-работа (`реализация`), куда роль
уводит узел стрелкой `start`. Так видно, кто ждёт, а кто в работе, и роль не срабатывает на узле дважды.

### `executors`

```yaml
executors:
  читатель:    { type: claude, model: sonnet, args: [--permission-mode, acceptEdits, --allowedTools, 'Bash(git log *)'] }
  разработчик: { type: claude, model: opus,   args: [--permission-mode, acceptEdits, --allowedTools, 'Bash(git *)', 'Bash(npm *)'], resumeWithin: 2h }
  заглушка:    { type: fake }
```

| Ключ | Что это |
|---|---|
| `type` | `claude` — живой агент `claude -p` в корне проекта; `fake` — заглушка с заготовками из `<проект>/fake/<роль>/` |
| `model` | уходит в `claude --model` (`sonnet`, `opus`, полное имя модели) |
| `args` | уходят в `claude` как есть, офис их не толкует. Здесь — права агента, см. [prompts.md](prompts.md#права-агента) |
| `resumeWithin` | роль поднята снова раньше этого срока после конца прошлого захода — `claude --resume` той же сессии (агент помнит разговор); позже — чистый старт от проекции. По умолчанию `1h` |
| `takes` | что берёт каждый агент этого исполнителя из [`resources`](#resources), пока жив |

Запуск с `--fake` превращает **все** исполнители в заглушки, что бы ни было написано в `type`.

### `roles`

```yaml
roles:
  реализатор:
    executor: разработчик
    prompt: office/roles/реализатор.md
    when: { kind: заявка, state: к реализации }
    needs: [критерий]
    sees:
      - { kind: постановка, from: [self, ancestors] }
      - { kind: отчёт }
    arrows:
      start: реализация
      outcomes: { готово: приёмка, не могу: отклонена }
```

| Ключ | Обязателен | Что это |
|---|---|---|
| `executor` | да | имя из `executors` |
| `prompt` | да | путь к промпту, относительно `office.yaml`. Файл читается при старте: нет файла — офис не стартует |
| `when` | да | предикат: на каких узлах нужен агент этой роли (условие, см. ниже) |
| `needs` | нет | поля, без которых роль не поднимается: узел «не дозрел» и молча ждёт, пока поле допишут |
| `sees` | нет | какие артефакты класть в проекцию. Без `sees` — ни одного (только карточка узла и области) |
| `arrows.start` | нет | состояние узла на время захода. Уводит узел из-под предиката, чтобы роль не сработала снова |
| `arrows.outcomes` | нет | исход → состояние узла. Если задано, **другие исходы офис не примет** |

Когда офис поднимает роль на узле (всё сразу):

- узел — лист (у него нет детей);
- `when` истинно, все поля из `needs` непустые;
- на ключе `роль/узел` нет живого или ждущего агента;
- роль ещё не отработала в текущей эпохе состояния узла (закончила заход и узел не сменил состояние — второй раз не поднимут);
- роль не потеряна трижды подряд (иначе — только вручную кнопкой роли на карточке узла).

Стрелки:

- `start` — при подъёме узел переходит в это состояние. Агент пропал без результата — узел возвращается туда, где был.
- `outcomes` — агент заявил исход → офис переводит узел. Исход, которого нет в `outcomes`, офис отклонит, и заход
  будет считаться потерянным. Без `outcomes` любой исход принимается, но узел остаётся, где был.

`sees` — список правил `{ kind, from }`:

- `kind` — вид артефакта или `'*'`;
- `from` — чьи артефакты: `self` (этого узла, по умолчанию), `ancestors` (родителя и выше), `children` (детей).

В проекцию попадает артефакт, который подходит под любое правило **и** адресован этой роли или `'*'`.
Остальные адресованные роли артефакты офис перечислит в `проекция/артефакты/не-вложено.md`: агент может их дотянуть.

### `transitions`

```yaml
transitions:
  - { kind: заявка, from: приёмка, to: готово,       when: { answer: { request: приёмка, is: принять } } }
  - { kind: заявка, from: приёмка, to: к реализации, when: { answer: { request: приёмка, is: вернуть } } }
  - { kind: заявка, from: [анализ, разбита], to: готово, when: { children: { all: [готово, отклонена] } } }
```

`kind` и `from` (одно состояние или список) выбирают узлы, `when` — условие, `to` — куда. Состояния `from` и `to`
должны быть у этого рода. Переходы проверяются каждый тик по всем узлам.

### `spawns`

```yaml
spawns:
  - { artifact: курс, kind: заявка, state: к анализу, requires: [описание], maxOpen: 2 }
```

Когда на узле опубликован артефакт вида `artifact`, офис создаёт по дочернему узлу на каждый элемент списка `nodes`
из шапки артефакта. Элемент — набор строковых полей будущего узла:

```yaml
kind: курс
audience: ['*']
nodes:
  - { описание: Страница входа по паролю }
  - { описание: Восстановление пароля по почте }
```

- `kind`, `state` — род и начальное состояние детей. Выбирай состояние, в которое **не смотрит** роль,
  которая разбивает, — иначе она разобьёт детей снова.
- `requires` — поля, обязательные у каждого элемента `nodes`. Нет поля — офис отклонит весь артефакт.
- `maxOpen` — сколько детей одного родителя может быть открыто одновременно (не в `closed`). Остальные ждут
  и рождаются по мере закрытия.

Родитель с детьми становится учётным: роли на него не поднимаются. Закрыть его — переходом по `children`.

### `requests`

```yaml
requests:
  - id: приёмка
    when: { kind: заявка, state: приёмка }
    question: Реализатор сдал работу. Принять?
    options: [принять, вернуть, отложить]
    default: отложить
    deadline: 3d
```

Офис открывает запрос на узле, где `when` истинно, — **один раз за эпоху состояния**. Человек отвечает в дашборде
кнопкой. Вышел `deadline` — офис сам отвечает `default` (он обязан быть одним из `options`). Сам ответ узел
не двигает: двигают переходы с условием `answer`. Ответ без перехода — ничего не происходит.

### `resources`

```yaml
resources:
  машина: 1        # стенд и тесты грузят её целиком
  opus: 3          # столько тяжёлых сессий тянем одновременно

executors:
  реализатор:  { type: claude, model: opus, takes: { машина: 1, opus: 1 } }
  тестировщик: { type: claude, model: opus, takes: { машина: 1, opus: 1 } }
  аналитик:    { type: claude, model: opus, takes: { opus: 1 } }
  штурман:     { type: claude, model: sonnet }        # ничего не берёт — не ограничен
```

Ресурс — имя и ёмкость, целое от нуля. Исполнитель (`executors.*.takes`) и роль (`roles.*.takes`) говорят,
сколько чего берёт агент на время жизни; доля роли перекрывает долю исполнителя по одноимённому ресурсу.
Агент поднимается, только если **всё**, что он берёт, помещается в свободное.

- «Тестировщик и разработчик — один в сумме» — оба берут `машина: 1` при ёмкости `1`.
- Веса: `opus: 3` при ёмкости `3` — роли нужна вся ёмкость, она подождёт, пока разойдутся трое лёгких.
- Считаются **живые** агенты. Агент, который умер и ждёт ответа человека, ничего не держит,
  но проснётся тоже только в свободное.
- Кому не хватило, тот просто не поднимается: узел остаётся в своём состоянии, в журнал ничего не пишется,
  на следующем тике офис пробует снова. Очередь — по старшинству узлов. Роль, вызванная человеком руками, тоже ждёт.
- Ёмкость `0` — рубильник: никто, кто берёт этот ресурс, не поднимется. Незнакомый ресурс в `takes` — ошибка загрузки.

### `areas`

```yaml
areas:
  api: [src/api/**]
  интерфейс: [src/ui/**, public/**]
```

Офис карту не толкует: кладёт её в `проекция/области.md` каждому агенту. Нужна, чтобы роли говорили
об одних и тех же частях проекта (аналитик пишет поле `область: api`, реализатор знает, где это).

### `askDeadline`

```yaml
askDeadline: 1d
```

Дедлайн вопроса агента (`вопрос.md`), если агент не указал свой. По умолчанию `24h`.

## Язык условий

Условие стоит в `roles.*.when`, `transitions[].when` и `requests[].when` и всегда вычисляется для одного узла.
Объект условия — это «И» всех его ключей.

| Ключ | Истинно, когда | Пример |
|---|---|---|
| `kind` | род узла — один из | `kind: заявка` · `kind: [заявка, ошибка]` |
| `state` | состояние узла — одно из | `state: новая` · `state: [новая, к анализу]` |
| `fields` | все эти поля у узла непустые | `fields: [критерий, область]` |
| `artifact` | на узле есть артефакт этого вида (и с такими значениями в шапке) | `artifact: { kind: отчёт }` · `artifact: { kind: ревью, where: { итог: годно } }` |
| `result` | роль заявила исход на этом узле **в текущей эпохе** (без `outcome` — любой) | `result: { role: ревьюер, outcome: годно }` |
| `answer` | на объявленный запрос дан такой ответ **в текущей эпохе** | `answer: { request: приёмка, is: принять }` |
| `children` | состояния детей: `all` — дети есть и все в одном из; `any` — хоть один в одном из; `none` — ни одного в | `children: { all: [готово, отклонена] }` |
| `all` | все подусловия | `all: [{ state: приёмка }, { fields: [замечания] }]` |
| `any` | хотя бы одно подусловие | `any: [{ state: новая }, { state: к анализу }]` |
| `not` | подусловие ложно | `not: { fields: [замечания] }` |
| `judge` | человек ответил «да» на суждение (в текущей эпохе) | `judge: { id: по-постановке, ask: Код соответствует постановке? }` |

Пример: переход по вердикту ревьюера — ревьюер заявляет исход, переход читает его.

```yaml
transitions:
  - { kind: заявка, from: ревью, to: приёмка,      when: { result: { role: ревьюер, outcome: годно } } }
  - { kind: заявка, from: ревью, to: к реализации, when: { result: { role: ревьюер, outcome: переделать } } }
```

То же обычно проще стрелками самого ревьюера: `outcomes: { годно: приёмка, переделать: к реализации }`.
`result` нужен, когда исход одной роли должен двигать узел вместе с другими условиями.

## Где условия ведут себя неожиданно

- **За тик на узле срабатывает один переход — первый подходящий по порядку в `transitions`.** Следующий
  проверится уже от нового состояния в следующем тике. Порядок в списке — это приоритет.
- **За шаг на узле поднимается одна роль — первая подходящая по порядку в `roles`.** Если у двух ролей один
  предикат и нет `start`, поднимутся обе — по очереди, в соседних тиках. Разводи роли по разным состояниям.
- **`result` и `answer` действуют только в эпохе.** Узел ушёл из состояния и вернулся — прошлого ответа
  «принять» больше нет, запрос откроется снова. Зато **`artifact` эпохи не знает**: однажды опубликованный артефакт
  делает условие истинным навсегда. Для «сделано в этот раз» используй `result`.
- **`answer` видит только запросы из `requests`** — не вопросы, которые агент задал сам через `вопрос.md`.
  Ответ на вопрос агента получает только он сам (его поднимут с ответом в `повод.md`).
- **Запрос открывается раз в эпоху.** Ответил человек — повторно в этом состоянии запрос не откроется, даже если
  перехода по ответу нет. Узел застрянет. На каждый вариант `options` нужен переход (или сознательное «ничего»).
- **`children.all` на узле без детей ложно**, `children.none` — истинно.
- **`judge` пока решает человек.** Условие с `judge` не выполнено, пока нет вердикта; узел и вопрос появляются
  в дашборде в блоке «Ожидают суждения» с кнопками «да / нет». Ключи условия вычисляются по порядку записи,
  поэтому `judge` ставь последним: `{ state: ревью, judge: {…} }` спросит человека только про узлы в `ревью`.
- **Гейтов нет.** «Не пускать дальше без человека» собирается из запроса и переходов по `answer`:
  состояние-ожидание, объявленный запрос на нём и переход на каждый вариант. Пример — схема «согласование» в [recipes.md](recipes.md).
- **Предикат роли без `kind`** срабатывает на узлах любого рода с таким состоянием. С одним родом это неважно.

Отложено и **не работает**, даже если встретится в старых текстах: аренды и потолки мест, бюджеты, гейты,
подписки, MCP, исполнители кроме `claude` и `fake`.
