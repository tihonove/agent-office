# Порядок настройки

Три шага, каждый — на своём уровне цены: манифест проверяется бесплатно при старте, путь заявки — бесплатно
на заглушках, и только последний шаг тратит модели.

```
1. манифест + промпты + заглушки      →  agent-office <проект> --fake стартует без ошибок манифеста
2. прогон на заглушках                →  заявка из дашборды проходит путь до конца
3. живой запуск                       →  agent-office <проект>
```

Предусловия — [prerequisites.md](prerequisites.md).

## Шаг 1. Манифест, промпты, заглушки

1. Выбери схему в [recipes.md](recipes.md) и скопируй её каталог в корень проекта целиком:

   ```
   cp -r $(npm root -g)/@tihonove/agent-office/docs/recipes/конвейер/. <проект>/
   ```

   Получится `office.yaml`, `office/roles/*.md`, `fake/<роль>/*.md`. Схема не подходит — начни с ближайшей и правь
   по [manifest.md](manifest.md). Пакет стоит в своём префиксе (`npm install -g --prefix …`) — `npm root -g`
   надо звать с тем же `--prefix`, или возьми путь к `docs/` явно.
2. Допиши в `.gitignore` проекта `.office/` и `.worktrees/`.
3. Подгони под проект:
   - **`args` исполнителей** — команды, которые ролям нужно запускать (тесты, сборка): `--allowedTools 'Bash(<команда> *)'`;
   - **промпты** `office/roles/*.md` — как в проекте проверять работу, где лежит важное, чего не трогать;
   - **`areas`** — если хочешь, чтобы роли называли части проекта одинаково;
   - **первую строку `office.yaml`** (`$schema=…`) — в схемах она указывает на пакет, установленный в проект
     (`./node_modules/…`). При глобальной установке замени на абсолютный путь
     `$(npm root -g)/@tihonove/agent-office/dist/manifest.schema.json`. На работу офиса строка не влияет — только на подсказки редактора.
4. **Заглушки** `fake/<роль>/` — по каталогу на **каждую** роль. Файлы копируются в `out/` назначения как есть при
   каждом подъёме роли, так что это ровно то, что оставил бы агент: `артефакт-*.md` и `результат.md`.
   Исход в `результат.md` должен быть из `arrows.outcomes` роли, поля — те, что ждут `needs` следующих ролей.
   Заглушка задаёт **один** путь и не знает, на каком узле её подняли (в готовых схемах отчёт пишет «ветка n-x» на любом узле);
   чтобы проверить другую ветку (например, `отказ`), поменяй файл и перезапусти прогон.

Переименовал роль, состояние или вид артефакта — поищи старое имя во всём: `office.yaml`, промптах, `fake/`.

## Шаг 2. Прогон на заглушках

```
agent-office <проект> --fake
```

**Старт.** Офис печатает `офис: <проект> (исполнители-заглушки)` и `дверь: http://127.0.0.1:4700`.
Ошибки манифеста — список `манифест …/office.yaml:` с местом каждой ошибки, и офис не стартует; разбор —
[errors.md](errors.md). Порт занят — `--port 4710`.

**Путь заявки.** Открой `http://127.0.0.1:4700`:

1. «Вбросить заявку»: форма уже подсказывает поля, без которых первая роль не поднимется (её `needs`).
   Заполни `описание` и нажми «вбросить».
2. В «Дереве работы» появится узел; за пару тиков (тик — 2 секунды, `--tick`) он пройдёт роли на заглушках.
   Возле узла — значки назначений ролей.
3. Где нужен человек — блок «Запросы к тебе» с кнопками вариантов. Отвечай, пока узел не придёт в конечное состояние.
4. Для «вернуть»/«переделать» сначала запиши узлу поле `замечания` на карточке узла («Поля» → «записать»),
   потом отвечай: роль, к которой вернётся узел, увидит поле в `узел.md`.

Без браузера — то же через HTTP-дверь (её же зовёт дашборда). Запустил офис с `--port` — меняй порт и в адресах.

```
curl -s -XPOST localhost:4700/api/nodes -H 'content-type: application/json' -d '{"fields":{"описание":"проверка"}}'
                                               # → {"ok":true,"result":"n-1"} — id нового узла
curl -s localhost:4700/api/snapshot            # nodes[].state; requests[]: у открытого нет ключа answer,
                                               #   у отвеченного answer = {"option":"принять","by":"human"|"deadline"}; flags[]
curl -s -XPOST localhost:4700/api/requests/r-1/answer -H 'content-type: application/json' -d '{"answer":"принять"}'
curl -s -XPOST localhost:4700/api/nodes/n-1/fields -H 'content-type: application/json' -d '{"fields":{"замечания":"…"}}'
curl -s -XPOST localhost:4700/api/nodes/n-1/invoke -H 'content-type: application/json' -d '{"role":"аналитик"}'
                                               # вызвать роль руками: так возвращают отложенную заявку
curl -s localhost:4700/api/facts               # весь журнал — то же, что .office/journal.jsonl
```

Команды отвечают `{"ok":true,…}` или `{"ok":false,"error":"…"}` с причиной (например, «на запрос r-1 уже дан ответ»).

**Прогон прошёл**, когда узел дошёл до конечного состояния, флагов нет, а в журнале нет `call.rejected` и `agent.lost`.

Каждый прогон `--fake` пишет в тот же `.office/`. Перед живым запуском (или чтобы начать заново) останови офис
и удали `.office/` — состояние целиком в нём.

## Шаг 3. Живой запуск

```
agent-office <проект>
```

Офис работает, пока жив процесс; остановка (Ctrl+C) ничего не ломает — при следующем старте он продолжит
с журнала, а агенты, запущенные прошлым процессом, останутся наблюдаемыми по pid.

Первую живую заявку возьми маленькую и следи за ней: открой назначение роли на карточке узла → «повод» и «транскрипт».
Живой агент работает минуты; пока он жив, значок назначения — «работает».

## Как понять, что всё работает

**Дашборда** (`http://127.0.0.1:4700`):

- «Дерево работы» — узлы, их состояния и назначения ролей;
- карточка узла — поля (и запись поля), назначения (кнопки «повод», «транскрипт»), кнопки ролей (вызвать руками),
  артефакты, запросы, факты узла;
- «Запросы к тебе», «Ожидают суждения», «Флаги» — где нужен человек.

**Журнал** `.office/journal.jsonl` — по факту на строку, `{"type": …, "node": …, "payload": …}`. Офис печатает их и в консоль.

| Факт | Значит |
|---|---|
| `node.created` · `node.state` · `node.fields` | узел родился · сменил состояние · получил поля. `payload.reason` у `node.state`: `<роль>/<узел>: в работе` (стрелка `start`), `…: <исход>` (стрелка исхода), `…: потерян`, `переход по условию` (из `transitions`) |
| `agent.spawned` | офис поднял роль (`payload.reason` — повод, `projection` — какие артефакты вложены, `resume` — продолжена ли сессия; для заглушек `resume` ничего не значит) |
| `artifact.published` · `agent.finished` | роль опубликовала артефакт · заявила исход |
| `agent.waiting` | роль задала вопрос или просит дотянуть и ждёт |
| `agent.lost` | заход потерян: агент завершился без результата |
| `call.rejected` | офис не принял файл из `out/`; `payload.reason` — почему |
| `request.opened` · `request.answered` | запрос человеку открыт · отвечен (`by: deadline` — по молчанию) |
| `role.invoked` · `flag.raised` · `judge.verdict` | человек вызвал роль · флаг · суждение |

Быстрый взгляд: `grep -E 'call.rejected|agent.lost|flag.raised' .office/journal.jsonl`.

**Каталог назначения** `.office/назначения/<роль>/<узел>/`:

- `повод.md` — почему роль подняли (в том числе что офис отклонил в прошлый раз);
- `проекция/` — что роль видела;
- `out/принято/`, `out/отклонено/` — что роль сказала и что из этого офис принял;
- `транскрипт.jsonl` — полный вывод `claude`; здесь видно, если агенту не хватило прав или `claude` не запустился.

## Флаг и потерянный заход

**Потерянный заход** — агент завершился, а в `out/` нет ни `результат.md`, ни `вопрос.md`, ни `дотянуть.md`
(или они отклонены). Офис пишет `agent.lost`, возвращает узел из состояния `start` туда, где он был, и на следующем
тике поднимает роль снова — с поводом «Прошлое воплощение завершилось без результата» и причинами отказов.

После **трёх потерь подряд** офис поднимает **флаг** «пропал без результата 3 раза подряд» и перестаёт поднимать
эту роль на узле сам. Разберись по транскрипту и `out/отклонено/`, поправь промпт, права или заглушку, перезапусти
офис и вызови роль руками — кнопкой с её именем на карточке узла. Счётчик потерь при этом сбрасывается.

**Флаг** вообще — «человек, посмотри». Его поднимает агент (`флаг-*.md`) или офис. Флаг ничего не двигает и не блокирует.
