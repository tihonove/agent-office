# Частые ошибки

## Офис не стартует

При старте офис проверяет манифест и печатает **все** ошибки сразу, затем выходит:

```
Error: манифест /path/to/проект/office.yaml:
  - roles.аналитик: исполнитель «gpt» не объявлен в executors
  - transitions[0]: у рода «заявка» нет состояния «закрыта»
```

Слева — место в манифесте (`roles.аналитик.when`, `requests.0`, `transitions[2]`), справа — что не так.
Сначала проверяется форма (по схеме); ошибки смысла (ссылки между разделами) появятся, только когда форма верна —
после исправления формы может прийти вторая порция.

### Форма

| Сообщение | Причина | Исправление |
|---|---|---|
| `roles.аналитик: не должно иметь дополнительных полей («wen»)` | опечатка или лишний ключ | ключи — только из справочника [manifest.md](manifest.md) |
| `roles.аналитик.when: не должно иметь дополнительных полей («status»)` | неизвестный ключ условия | ключи условия: `kind state fields artifact result answer children all any not judge` |
| `roles.аналитик: должно иметь обязательное поле when («when»)` | нет обязательного ключа | у роли обязательны `executor`, `prompt`, `when` |
| `манифест: должно иметь обязательное поле inbox («inbox»)` | нет раздела | обязательны `inbox`, `kinds`, `executors`, `roles` |
| `requests.0: должно иметь обязательное поле deadline («deadline»)` | у запроса нет дедлайна | у запроса обязательны `id`, `when`, `question`, `options`, `default`, `deadline` |
| `executors.claude: должно иметь обязательное поле type («type»)` | у исполнителя нет типа | `type: claude` или `type: fake` |
| `kinds.заявка.states: должно быть array` · `requests.0.options: должно быть array` | строка вместо списка | `[a, b]` |
| `transitions: должно быть array` | переходы записаны картой | список: `- { kind, from, to, when }` |
| `roles.аналитик.arrows.outcomes: должно быть object` | исходы списком | карта `исход: состояние` |
| `roles.аналитик.sees.0: должно быть object` | `sees: [постановка]` | `sees: [{ kind: постановка }]` |
| `roles.аналитик.sees.0.from.0: должно быть равно одному из разрешенных значений` | `from: [parent]` | `self`, `ancestors`, `children` |

### Смысл

| Сообщение | Причина |
|---|---|
| `inbox: у рода «заявка» нет состояния «Новая»` | имена сравниваются буква в букву, с регистром |
| `transitions[0]: у рода «заявка» нет состояния «закрыта»` | `from`/`to` перехода — не из `states` рода |
| `kinds.заявка.closed: у рода «заявка» нет состояния «закрыта»` | `closed` — подмножество `states` |
| `spawns[0]: у рода «заявка» нет состояния «черновик»` | начальное состояние детей — не из `states` |
| `roles.аналитик.arrows: состояния «анализз» нет ни у одного рода` | опечатка в `start` или `outcomes` |
| `roles.аналитик.when: род «задача» не объявлен в kinds` | `kind` в условии — не из `kinds` |
| `roles.аналитик: исполнитель «gpt» не объявлен в executors` | `executor` роли — не из `executors` |
| `transitions[0].when: запрос «приёмкаа» не объявлен в requests` | `answer.request` — не `id` из `requests` |
| `transitions[0].when: роль «тестер» не объявлена в roles` | `result.role` — не из `roles` |
| `requests.приёмка: default должен быть одним из options` | исход по молчанию — не из вариантов |
| `requests.приёмка.deadline: не понимаю длительность «1 день»: жду число и s\|m\|h\|d, например 24h` | формат длительности (также `askDeadline`, `resumeWithin`) |

### Прочее на старте

| Что видно | Причина |
|---|---|
| `В <проект> нет манифеста office.yaml.` | манифест не в корне переданного каталога или назван иначе |
| `ENOENT: no such file or directory, open '…/office/roles/аналитик.md'` | нет файла промпта; путь `prompt` — относительно `office.yaml` |
| `YAMLParseError: …` | синтаксис YAML: отступы, незакрытая скобка, `:` внутри значения без кавычек |
| `исполнитель «x»: не знаю тип «gpt»` | `type` — только `claude` или `fake` |
| `EADDRINUSE … 4700` | порт занят (другой офис?): `--port 4710` |

## Офис стартовал, но заявка стоит

| Симптом | Причина | Где смотреть |
|---|---|---|
| заявка висит в `inbox`-состоянии, агентов нет | ни у одной роли `when` не совпадает с `inbox`, или нет полей из `needs` | форма вброса подсказывает `needs`; карточка узла → «Поля» |
| узел стоит в состоянии-очереди, агентов нет | у следующей роли нет полей `needs` — прошлая роль их не записала | `узел.md` в проекции; `fields` в `результат.md` прошлой роли |
| роль поднимается снова и снова, потом флаг | исход не из `arrows.outcomes`, или нет `результат.md` | `call.rejected` в журнале, `out/отклонено/`, `повод.md` |
| на `--fake` роль теряется трижды и флаг | нет каталога `fake/<роль>/` или в нём нет `результат.md` | `fake/` в корне проекта, имя каталога = имя роли |
| запрос отвечен, узел не двинулся | нет перехода на этот вариант, или `is:` с опечаткой (валидатор варианты не сверяет) | `transitions` с `answer` |
| узел вернулся в состояние, а запрос не открылся | запрос открывается раз в эпоху; если узел не выходил из состояния — повторно не откроется | факты узла |
| родитель навсегда в `разбита` | нет перехода по `children`, или дети застряли | переходы, состояния детей |
| исход «разбито» принят, детей нет | артефакт порождения отклонён: нет `nodes`, не строки, нет полей из `requires` | `call.rejected`; пример шапки в промпте |
| порождённые дети разбиваются снова | дети рождаются в состоянии, на которое смотрит разбивающая роль | `spawns[].state` |
| реализатор не видит постановку | вид или аудитория артефакта не совпадают с `sees` роли | `проекция/артефакты/не-вложено.md` |
| вторая роль с тем же `when` поднимается на тот же узел | нет `arrows.start`: узел не уходит из-под предиката | разведи роли по состояниям, задай `start` |
| условие с `judge` не срабатывает | вердикта нет: суждение выносит человек | дашборда → «Ожидают суждения» |

## Живой агент ничего не делает

| Симптом | Причина |
|---|---|
| в транскрипте `{"type":"office","error":"Error: spawn claude ENOENT"}`, затем потери | `claude` не в `PATH` процесса офиса |
| в транскрипте просьба авторизоваться | `claude` не авторизован для этого пользователя |
| в транскрипте отказы в правах на Bash или правку, `out/` пуст | не хватает `args`: `--permission-mode acceptEdits`, `--allowedTools 'Bash(…)'` |
| агент правит основное дерево, мешает другим | промпт не велит работать в worktree — офис этого за тебя не решит |
| агент ждёт ответа внутри захода | промпт не говорит «спросил — завершайся»; вопрос — файлом `вопрос.md` |

## Офис упал или замолчал на ходу

Офис переживает рестарт: журнал append-only, а агенты остаются наблюдаемыми по pid-файлам — поднимайте его
снова той же командой, ничего доделывать руками не надо. Но пока он лежит, живые агенты работают в пустоту:
их вывод никто не забирает, и заходы придётся повторять.

| Что видно | Причина | Исправление |
|---|---|---|
| `реализатор/n-8: транскрипт не пишется, агент работает без него` + `ENOSPC` | на диске нет места (или каталог назначения снесли) | освободить место; офис жив, обрывается только транскрипт этого захода |
| `тик упал … ENOSPC` | факты не дописываются в журнал, сверка не доходит до конца | освободить место: следующий удар сердца повторит сверку целиком |
| на старте `журнал …, строка 376: не разбирается — факт дописан не до конца` | прошлый процесс оборвал дозапись (кончилось место, упало железо) | обрезать оборванную строку — факт в журнале ровно один на строку |
| роли теряются подряд у всех узлов, в транскриптах обрывы | агентам тоже некуда писать | сначала место на диске, потом флаги |
| `EADDRINUSE … 4700` после падения | прошлый процесс ещё держит дверь | дождаться его выхода или `--port 4710` |

### Куда уходит место

Офис за собой чистит только `out/` (разобранное уезжает в `принято/` и `отклонено/`), всё остальное растёт:

| Что | Сколько | Кто чистит |
|---|---|---|
| `.office/назначения/<роль>/<узел>/транскрипт.jsonl` | мегабайты за заход, дописывается при каждом воплощении | человек: заходы закончились — каталог можно снести целиком |
| worktree-каталоги по узлам (`.claude/worktrees/n-7/…`) | гигабайты: у каждого свои `node_modules` и сборка | человек или промпт роли: офис про worktree не знает и не убирает |
| сессии `claude` (`~/.claude/projects/…`) | растут с каждым `--resume` | человек |

Долгий прогон на десяток узлов — это десятки гигабайт. Проверяйте `df -h` перед тем, как оставить офис на ночь.
